---
title: "Configuring Album Display Settings in VAMS Profiles"
sidebarTitle: "Display Settings"
description: "Control which metadata fields are included in your API responses so any external frontend can render your albums exactly the way you intend."
---

Display settings let you define exactly how your album content is presented when it is fetched through the VAMS API. Every API response for your albums includes an `album_display_settings` object carrying your preferences — brand colors and the visibility of each metadata field — so external frontends and headless clients can render your content exactly the way you intend without any additional configuration on their end.

These settings are per-account and apply uniformly to all albums served under your API key. You can update them at any time from the **Profile** page under the **Album Display Settings** section.

<Tip>
  Changes to your display settings take effect immediately on the next API call — there is no cache to clear or deployment to trigger.
</Tip>

## Brand Colors

Two hex color values are embedded in your API responses so external frontends can apply consistent branding without hard-coding colors on their side. These values are read-only from the **Album Display Settings** section and are reflected in the API response as `main_color` and `secondary_color`.

| Field | Default | Description |
|-------|---------|-------------|
| `main_color` | `#4F46E5` | Your primary brand color — use it for dominant UI elements like headings, buttons, and active states. |
| `secondary_color` | `#10B981` | Your accent or supporting brand color — use it for highlights, borders, tags, and secondary interactive elements. |

<Note>
  Brand colors are set to the defaults above when your account is first created. To update them, contact support or use the VAMS API directly to patch your display settings.
</Note>

## Metadata Toggle Fields

Each toggle controls whether a specific metadata field is included in your API response payloads. Disabling a field does not delete the underlying data — it simply omits it from the response so your frontend doesn't have to filter it out manually.

All seven fields are **enabled by default** when you first create your account.

<Accordion title="Title">
  **Default:** enabled

  The title of the album image or asset. Enable this if your frontend displays image titles as headings, captions, or overlay labels.
</Accordion>

<Accordion title="Author">
  **Default:** enabled

  The name of the person credited with creating the image or asset. Enable this for portfolios, editorial sites, or anywhere attribution needs to be surfaced.
</Accordion>

<Accordion title="Caption">
  **Default:** enabled

  A descriptive or narrative caption for the image. Enable this when your frontend renders body text beneath or alongside images.
</Accordion>

<Accordion title="Alt Text">
  **Default:** enabled

  The accessibility description for the image. Keep this enabled whenever your frontend renders images — it is essential for screen readers and SEO.
</Accordion>

<Accordion title="Date Created">
  **Default:** enabled

  The date the image or asset was originally created. Enable this for timelines, galleries sorted by date, or anywhere a timestamp adds context.
</Accordion>

<Accordion title="Location">
  **Default:** enabled

  The geographic location associated with the image. Enable this for travel photography, event documentation, or location-tagged portfolios.
</Accordion>

<Accordion title="Tags">
  **Default:** enabled

  A list of descriptive tags attached to the image. Enable this to support filtering, search, or tag-cloud features in your frontend.
</Accordion>

## Saving Your Settings

Once you have toggled the fields you want, scroll to the bottom of the **Album Display Settings** section and click **Save Display Settings**. The page will confirm your new preferences have been saved.

<Note>
  All toggles are enabled by default when you first create your account. You only need to visit this section if you want to customise which fields are included in your API responses.
</Note>
