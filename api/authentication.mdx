The VAMS API uses **API key authentication**. Every request must include your personal API key in the `X-API-Key` HTTP header. There are no sessions, cookies, or OAuth tokens involved — the header is the only credential the API checks. All responses are scoped to the account that owns the key, so you can safely embed it in server-side code without exposing other users' data.

## Getting Your API Key

1. Log in to your VAMS account.
2. Navigate to your **Profile** page.
3. Locate the **API Key** section.
4. Copy the key shown there.

<Warning>
  Treat your API key like a password. Anyone who holds it can read all of your published content through the API. Do not commit it to public repositories or expose it in client-side JavaScript that runs in a browser.
</Warning>

## Sending the Header

Include the key as the value of the `X-API-Key` header on every request.

<CodeGroup>

```javascript JavaScript
const response = await fetch('https://<your-vams-domain>/api/albums', {
  headers: {
    'X-API-Key': 'your-api-key-here'
  }
});

const data = await response.json();
console.log(data);
```

```bash curl
curl https://<your-vams-domain>/api/albums \
  -H "X-API-Key: your-api-key-here"
```

</CodeGroup>

## Testing Your Key

Use the `/api/test` endpoint to confirm your key is valid before making real requests. A successful response echoes back your account name and the current timestamp.

<CodeGroup>

```javascript JavaScript
const response = await fetch('https://<your-vams-domain>/api/test', {
  headers: {
    'X-API-Key': 'your-api-key-here'
  }
});

const data = await response.json();
console.log(data.user);      // your account name
console.log(data.timestamp); // current server time
```

```bash curl
curl https://<your-vams-domain>/api/test \
  -H "X-API-Key: your-api-key-here"
```

</CodeGroup>

**Example response:**

```json
{
  "message": "API key authentication successful",
  "user": "Jane Doe",
  "timestamp": "2024-09-15T10:30:00.000Z"
}
```

<Note>
  The `/api/test` response is not wrapped in the standard `success`/`data` envelope used by the other endpoints — it returns `message`, `user`, and `timestamp` at the top level.
</Note>

## Authentication Errors

When the `X-API-Key` header is missing or contains an invalid key, the API returns a `401 Unauthorized` response:

```json
{
  "success": false,
  "message": "Unauthorized"
}
```

<Tip>
  Double-check that the header name is spelled exactly as `X-API-Key` — the API performs a case-sensitive header lookup.
</Tip>

## Rate Limiting

Every API key is limited to **60 requests per minute**. Once you exceed that limit the API returns `429 Too Many Requests` and stops processing further requests until the current one-minute window expires.

```json
{
  "success": false,
  "message": "Too Many Requests"
}
```

If your integration is read-heavy, consider caching responses on your side to avoid hitting the limit during traffic spikes.
